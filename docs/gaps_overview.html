What a Gap means

You asked whether a Gap means a count mismatch, or fewer than 1440 one-minute Bars in a day. Neither. This page says what a Gap really is, in plain words. The code stays the source of truth.

A Gap is a list of times, not a count.

1 · What I said

source: internal/app/gaps.go

I said this:

The sentence that did not land “A Gap is expected-minus-present per open_time inside Coverage, recorded at the end of a Backfill.”

Every word is true. None of it helps. Here is the same thing, plainly.

The plain version The system knows which Bars it should have. It knows which Bars it holds. A Gap is the times on the first list that are absent from the second.

So it is a register, not a headcount. A teacher does not count heads and stop. A teacher reads the names and marks who is absent.

2 · One day, three missing minutes

source: internal/domain/calendar.go

Take one day of one-minute Bars for BTCUSDT. Binance trades all day, every day. So the system expects 1440 Bars, one per minute.

The first is 00:00. The last is 23:59. The end of your range is never expected — you asked up to midnight, not including it.

Now say three Bars are absent: 10:00, 10:01 and 15:30. That is two Gaps, not three, and not one.

Two absent minutes that touch are one Gap. A Gap that stands alone is one minute wide. The Gap runs from its first absent minute to one minute past its last.

Your two guesses, answered A count below 1440 and a count mismatch both say yes, something is off. Neither says which minutes. One outage of sixty minutes and sixty scattered dropouts give the same count. They are not the same problem, so the system records the times.
Why the second Gap ends at 15:31concept

A Bar is named by the minute it opens. The Bar named 15:30 covers 15:30 up to 15:31. So a Gap that holds only that Bar spans 15:30 to 15:31. Ranges always include the start and exclude the end.

3 · Why counting is the wrong question

source: internal/app/complete.go, CONTEXT.md

A count needs a total to compare against. The system refuses to guess that total for data you never asked for.

Coverage is the list of ranges you have actually asked for, through a Backfill. Outside Coverage the answer is not missing. It is unknown.

Inside Coverage

Absent Bars become Gaps

You asked for this day. The system knows what it should hold. Anything absent is recorded, with its times.

Outside Coverage

Nothing is claimed

You never asked for this day. The system says the range is not Complete, and lists no Gaps. There is nothing to be missing yet.

The one trap An empty Gap list does not mean the data is good. It can also mean the range was never fetched. Ask whether the range is Complete — that question checks Coverage first.

There is a second thing worth knowing. A Gap is a stored record, written when a Backfill finishes. Asking for Gaps reads that record. It does not re-check the Bars.

So Bars removed behind the system's back stay invisible until the next Backfill over that range. never the read path does not silently re-scan your data.

How I confirmed the record is not recomputedevidence

On a scratch database I deleted three Bars directly, then restarted the service. Asking for Gaps still returned an empty list, and the range still reported Complete. Detection runs at the end of a Backfill, in internal/app/backfill.go:361 — nowhere else.

4 · How it decides

source: internal/app/gaps.go

1A Backfill finishes, over the range that landed.
2The system keeps only the part of that range inside Coverage.
3The Provider's Trading Calendar lists every Bar time expected there. Binance runs 24/7, so that is every minute.
4It strikes out the times it holds, and the times an operator already settled.
5What is left is grouped into runs of neighbouring times. Each run becomes one Gap.

A Gap you settle as ignored or unrecoverable stops blocking Complete. A Gap whose Bars later arrive becomes repaired by itself, on the next Backfill over its range.

The technical flowengineers

DetectGaps intersects the requested range with each Coverage range. Inside each piece it walks calendar.Expected(piece, timeframe), an ascending sequence of open_time values aligned to timeframe boundaries measured from the Unix epoch. A run of consecutive absent values flushes into one domain.Gap with range [first, last + timeframe).

Open Gaps in the range are then replaced wholesale, so a Gap that has since been filled disappears. A Gap straddling the range edge widens the range first, so it is re-detected in full.

Because the walk is over the calendar's sequence, a market-closed period neither becomes a Gap nor breaks a run across it. Binance uses domain.Continuous, which expects every boundary.
